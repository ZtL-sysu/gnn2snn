# Actual ARC/native writing boundary

`native_arc.py` calls the installed ARC stage functions rather than substituting a direct draft for an ARC execution. A scoped runtime adapter disables historical-context collectors and restricts prior scientific reads. Each actual `llm.chat` call emits only the installed writing adapter's `messages`; earlier manuscript sections may be included as authorized current draft. Provenance is stored separately. No original ARC prompt, history, stage ledger or reviewer installation note becomes writer context.

The live native writer is a fresh-context subagent with no inherited project conversation. It reads the emitted request and writes exactly `manuscript` and `notes`, plus a separate SHA-bound execution receipt. The ARC process waits for this actual live response; the response is not a canned fixture. It passes only manuscript text onward. Runtime records bind ARC executor/source hashes, bridge version, clean request, response, actual call stack and test/production identity. Native model identity is reported only to the extent exposed; requested model/effort is recorded in the separate receipt. No credentials, paid API probes, global model changes or edits to the external ARC clone occur.

`test_native_arc.py` invokes a real outline-stage function with a test-only capture exchange and adversarial historical canary. That fixture proves boundary isolation; it never counts as scientific writing. Production uses the file exchange with no test callback. Each production output still requires primary semantic review, response-format validation and a source/PDF audit. A DONE return or a hash is insufficient by itself.
