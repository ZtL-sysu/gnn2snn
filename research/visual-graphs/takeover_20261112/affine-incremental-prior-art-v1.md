# Affine-base residual coding: bounded prior-art screen

**Scope.** This is a targeted primary-source screen, not an exhaustive search or novelty determination. Project definition is the planned v2 dataflow in `../DERIVATION_PACKAGE_v2.md`: within one ANN-to-SNN conversion run on a fixed graph, write each identity-residual state as (h_l=h_0+q_l, e_l=e_0+r_l), where (q,r) are accumulated nonnegative ReLU residual branches; code each raw residual prefix once per layer with the unchanged differential source; feed (h_0+C[q_l]) to the shared node consumers A/B/D/E and (e_0+C[r_l]) to C; leave the residual skip on raw (q,r); keep the normalized sigmoid gate/controller recomputed as specified. All modes use a matched analog graph classifier head. This is not an established efficiency or novelty result.

## Closest primary sources

1. **Sigma-Delta Quantized Networks** — O’Connor & Welling, ICLR 2017, [paper](https://openreview.net/pdf?id=HkNRsU5ge), [author code](https://github.com/petered/sigma-delta). Section 3.1, Algorithms 1–2 (PDF pp. 2–3), defines a temporal difference latch (d_t=x_t-x_{t-1}), (x_0=0), and an integrator (y_t=y_{t-1}+d_t). Eq. (1) (p. 3) shows the linear-operator commute/rewrite (Delta_T(w(Sigma_T(x)))=w(x)), enabling communication of discretized changes through a deep net. The project’s source-unit form (e_t=t(a_t-a_{t-1})), (hat a_T=sum_{tle T} e_t/t) is a different time-weighted decoder, but the broad principles “encode activation changes,” “decode/update downstream linear work,” and “trade sparsity against approximation” are already prior art. The paper uses temporally redundant video frames and approximate rounded changes; it does not establish the project’s centered nonnegative residual coordinates, GatedGCN gate structure, or graph-conditioned normalized gate behavior.

2. **DeltaCNN: End-to-End CNN Inference of Sparse Frame Differences in Videos** — Parger et al., CVPR 2022, [paper](https://openaccess.thecvf.com/content/CVPR2022/html/Parger_DeltaCNN_End-to-End_CNN_Inference_of_Sparse_Frame_Differences_in_Videos_CVPR_2022_paper.html), [official code](https://github.com/facebookresearch/DeltaCNN). Section 3.1, Eqs. (1)–(6), pp. 12499–12500: linear convolution obeys (c(x+\delta x)=c(x)+c(\delta x)); for a nonlinear (f), it emits (\delta y=f(x+\delta x)-f(x)) while storing the prior accumulated input. Their accumulation/truncation buffers (x^A,x^T) prevent dropped small changes from drifting indefinitely. This is very close precedent for propagating temporal feature deltas and updating linear consumers from deltas; it specifically warns that nonlinearities need state and that sparse FLOPs do not automatically become real speedups. Difference: DeltaCNN updates frame-to-frame CNN feature maps with spatial masks and nonlinear accumulated-input buffers; project v2 codes a cumulative nonnegative residual coordinate within a bounded conversion horizon on a fixed graph, and has edge-dependent normalized messages and a live gate. Nothing in the paper makes the project’s affine split novel by itself.

3. **DynaGraph: Dynamic Graph Neural Networks at Scale** — Guan et al., [primary paper PDF](https://taesoo.kim/pubs/2022/guan%3Adynagraph.pdf). Section 3.1, pp. 3–4, describes caching the same graph aggregation/message (m_{x_t}) or (m_{h_{t-1}}) across GraphRNN gates before gate-specific linear projections; §3.2 fuses input graph convolutions across timesteps. This directly establishes that shared graph-message computation across multiple consumers/gates is a known GNN optimization. Its cached message is the same aggregation of identical graph/input state reused among gates; the project instead shares a *coded* node prefix across GatedGCN projections A/B/D/E and edge prefix for C, while gate coefficients depend on the current state and are recomputed/normalized. DynaGraph studies recurrent dynamic-graph workloads and sliding windows, not per-conversion-tick residual coding. A strong novelty/benefit comparison must still include ordinary shared-projection/CSE and caching controls; “one shared event stream rather than duplicated encoders” alone is not enough.

4. **Automating Incremental Graph Processing with Flexible Memoization (Ingress)** — Gong et al., PVLDB 14(9), 2021, [paper](https://vldb.org/pvldb/vol14/p1613-gong.pdf), [implementation branch referenced by project maintainers](https://github.com/alibaba/libgrape-lite/tree/ingress). Section 3, journal pp. 1615 onward, formulates incrementalization of vertex-centric programs by finding changed messages, replaying only affected regions, and canceling/compensating old/new messages (see §3 “Message-driven differentiation” and memoization policies). The paper includes GCN among target vertex-centric computations (Fig. 1). This covers a broad compiler/system precedent for deriving incremental graph execution from message differences and selecting caches. Its input change is graph/data updates between batch runs; project v2 keeps one visual graph and trained operator fixed and represents successive internal conversion activations as coded residual prefixes. It does not document the project’s gate-normalized differential path, but makes broad claims of “incremental graph computation from deltas” untenable.

5. **Differential Coding for Training-Free ANN-to-SNN Conversion (DCGS)** — Huang et al., ICML 2025, [paper](https://proceedings.mlr.press/v267/huang25i.html), [arXiv HTML Algorithm 2](https://arxiv.org/html/2503.00301v1), [author repository](https://github.com/h-z-h-cell/ANN-to-SNN-DCGS). Algorithm 2 (Appendix A, lines 419–437) describes differential graded coding at nonlinear units and identity differential units before linear layers, with bias initially placed in membrane potential; its ReLU conditional selects threshold treatment, while the replacement steps follow outside that condition. This is direct ANN-to-SNN source-coding precedent. The existing project source audit already records the important qualification: the pinned converter’s architecture-specific VGG/ResNet path and generic fallback differ, and selected GatedGCN branch conversion with dense analog controller is a project adaptation, not a full DCGS reproduction. Neither generic identity coding nor moving a fixed affine offset/bias out of repeated event input should be claimed as new.

## What is covered, and what remains testable

| Project element | Prior-art implication |
|---|---|
| Differential/temporal change coding and linear downstream updates | Established by Sigma-Delta and DeltaCNN; project-specific time weighting is not, by itself, a contribution claim. |
| Fixed affine base (h_0,e_0) separated from a residual coordinate; bias/base hoisting | Algebraic change of origin / affine reassociation and static bias handling are standard transformations. The split alone is not a novelty claim. |
| Common encoded prefix reused by several consumers | Shared aggregation/message caching in DynaGraph and general CSE/memoization in Ingress make reuse alone known. Project-specific operator/coordinate placement still needs an exact comparison. |
| Nonnegative accumulated (q,r), code only the residual before selected matrix consumers, raw skip preserved | Not established by the cited papers in this exact GatedGCN conversion dataflow. This is a candidate combination, not evidence of novelty; equivalent formulations may exist outside this bounded screen. |
| Dynamic sigmoid gate with graph-wise normalization | Not the central computation in the cited CNN/SDNN or generic incremental-graph systems. Project must demonstrate that gate recomputation/normalization remains correct and report its cost; no efficiency follows from coding the other inputs. |
| Fixed graph, individual graph classification, bounded T ticks | Different from video frame sequences (Sigma-Delta/DeltaCNN) and evolving-graph updates / recurrent snapshots (DynaGraph/Ingress). It is a workload distinction, not an intrinsic algorithmic advantage. |

## Evidence needed to distinguish the candidate

1. **Faithful controls:** same teacher/graph/order/threshold calibration/T/head for exact ANN, ordinary per-consumer DCGS-style coding, shared generic source-coded prefixes, first-layer-analog mode, and the affine-base residual mode. Include a CSE/cache control so gains cannot be attributed simply to avoiding duplicate projection/encoding work. State clearly that current project conversion is not a full DCGS reproduction.
2. **Mechanism evidence:** layer-by-layer teacher error and candidate error at each T; raw residual and coded-residual reconstruction error; per-site event density and nonzero-row density; separate gate pre-normalization logits, sigmoid gates, normalization denominator and message-output error. Vary graph degree/edge count and gate sharpness; report failures as well as wins.
3. **Error analysis:** derive or empirically validate how source reconstruction error propagates through ReLU residual accumulation, BN scaling, sigmoid gates and normalization (including a lower bound/near-zero distribution for the denominator). A generic linear Lipschitz bound is likely loose; test it against measured per-layer and final-logit errors. No claimed stability is supported by the cited sources for this exact normalized edge-gated recurrence.
4. **Real cost evidence:** count all source encoding/decoding, base application, projections, scatter/gather, dynamic gate and normalization, cache/state traffic, and analog head operations under the declared target hardware model; then measure an appropriate sparse implementation. DeltaCNN explicitly shows why sparse operation counts alone do not establish wall-clock acceleration. Do not call shared input coding a cost advantage until compared to the best fair shared-message baseline.

**Uncertainty boundary.** This review selected five close sources by mechanism and system setting; it did not search all SNN conversion, differential dataflow, graph compiler, or patent literature. DynaGraph is a direct overlap in shared graph messages across gates; DeltaCNN/Sigma-Delta are direct overlap in temporal activation deltas; Ingress covers generic incremental graph updates. These are enough to reject broad novelty language around delta coding, shared consumers, static offset hoisting, or incremental GNN execution. They do not establish whether the exact joint dataflow — centered nonnegative residual-prefix coding plus shared multi-projection consumers plus dynamic normalized graph gates in ANN-to-SNN graph classification — has prior exact implementation or a useful cost/accuracy frontier.
