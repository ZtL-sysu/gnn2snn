# Affine-base full-training code review v1

## Verdict

**Current observed runs pass this setting; the driver has a fail-closed gap for future environments.** Both scripts call `os.environ.setdefault('CUBLAS_WORKSPACE_CONFIG', ':4096:8')` before importing Torch. If a caller already has another value, the script retains it instead of enforcing the protocol's exact `:4096:8`. I checked `affine_cal1.json`, `affine_generic_s1_tr1.json`, and `affine_generic_s8_tr1.json`: each is complete and records `CUBLAS_WORKSPACE_CONFIG=:4096:8` and deterministic algorithms enabled, so these observed runs satisfy the frozen deterministic setting. The other four profile outputs were not present at review time; verify their runtime metadata before accepting the complete six-profile screen. For future launches, reject any pre-set conflicting value before importing Torch. This review did not modify the bound scripts.

## What matched the protocol

- **Calibration quantities:** the calibrator observes the native teacher at all four layer inputs and captures `abs(h), abs(e)` (8 raw sites). Post-BN hooks accumulate `ReLU(BN node/edge current)` across preceding layers and record the six nonnegative cumulative branch inputs before layers 1–3. This uses branch sums, not subtraction of large raw states. It checks once-per-batch capture, finiteness, and `[node-or-edge rows, 70]` shapes; hooks are removed in `finally`.
- **Full-train scope and statistics:** the loader is the official CIFAR10 `train` split in fixed order, wrapped in `LabelFreeGraphView`, with batch size 128 and no workers/shuffle. Calibration requires 45,000 graphs, 352 batches, and final batch 72 in both passes. Pass one computes channel maxima; pass two builds 512-bin per-channel/global histograms, uses the declared .999 quantile and 1e-6 floor, and records counts/thresholds/coverage. The independent statistic validator checks site set, row totals, histogram partitions, threshold reconstruction and finite values.
- **Teacher and provenance binding:** the calibrator validates the seed-41 run metadata, done marker, checkpoint, source manifest, and expected four-layer 5→70 GatedTeacher shape. It uses exclusive output creation and start/end hashes over the declared code, teacher source/checkpoint, protocol and processed train data. The profiler validates that calibration document against the currently loaded teacher, rechecks its bound inputs, binds the profile/helper/checker sources, calibration file, and pinned author source, then verifies unchanged inputs and source at the end. Output paths are restricted to the takeover directory and existing paths are refused.
- **Labels and teacher oracle:** both stages use the label-free dataset view; calibration and profile reject a batch with `y`. In the profile, the teacher forward is computed only to form reference logits/metrics. Candidate forward uses the affine-mode implementation separately and receives no teacher hidden states. Its metrics are agreement, logit MSE, and teacher-to-candidate KL, not ground-truth accuracy.
- **Modes and θ:** `profile_thresholds` selects generic raw sites at layers 0–3; first-analog uses exactly generic raw thresholds for layers 1–3; centered uses branch-cumulative thresholds for layers 1–3. The CLI is restricted to the protocol's two scales, 1 and 8. The affine helper preserves raw residual skips, with one node stream used by A/B/D/E and one edge stream by C; it is a dense reference implementation, not a cached or sparse backend.
- **Calls, prefixes and event accounting:** each full T4 profile checks exact site order, one warm-up per coded site per batch, four active calls per site, final tick counters, and the three prefix checkpoints (T1/T2/T4). Cumulative event statistics are partitioned into positive/negative/zero scalars, signed level counts and nonzero rows, with prefix bounds and exact row totals checked. Prefix logits are small graph-by-class arrays; the code counts three diagnostic head calls per batch and reports one normal endpoint head call per batch separately. The diagnostic T4 logits are reused as the T4 prefix, so they should not be described as an additional fourth head call.
- **Checks run:** `check_gated_affine_cal_v1.py` and `check_gated_affine_profile_v1.py` both passed under Conda `dyg-cold` on CPU. Their synthetic fixtures verify capture definitions against an independent recurrence, channel threshold behavior, label/eval/input/coverage rejection, source call and prefix accounting, independent metrics, and absence of official-data loading. The calibration check also exercises the actual teacher binding without loading the graph dataset.

## Evidence boundary

The official calibration/profile protocol is training-only and explicitly prohibits validation/test, accuracy claims, and efficiency claims. Agreement/MSE/KL are fidelity diagnostics against the frozen teacher. Prospective projection-add counts are a modeled component count; they do not include all dense gate/message/reduction/head work and are not a hardware measurement. Nothing in these scripts can establish sparse execution, end-to-end latency, energy, method novelty, or superiority.

The current calibration and two present generic-profile records have the expected deterministic metadata; the remaining four profile records still need the same metadata check when available. No GPU work was launched by this review.
